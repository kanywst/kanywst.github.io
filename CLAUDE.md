# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`kanywst`'s personal profile page (React + Vite → GitHub Pages at <https://kanywst.github.io/>).
It is **data-driven**: `src/data/profile.json` is the single source of truth, and the whole
page is rendered from it. There is no backend or router.

## Commands

```bash
npm install            # MUST run before trusting a build — see the TypeScript gotcha below
npm run dev            # local dev server
npm run build          # tsc && vite build — the real gate (typecheck + bundle)
npm run preview        # serve the production build (dist/)
npm test               # vitest run — App + profile.json contract
npm run lint           # eslint
node scripts/sync-profile.mjs      # rediscover selected work + refresh PRs/issues from the GitHub API (needs gh)
node scripts/sync-advisories.mjs   # refresh the security-advisories section (published GHSAs → advisories[])
```

`npm run build` is the CI gate; run `npm test` and `npm run lint` too before calling a change done.

## Architecture (the parts that span files)

- **`src/data/profile.json`** — single source of truth, two kinds of data:
  - *Curated* (hand-authored): `org` (0-draft blurb + repos), `profile`. These encode judgment.
  - *Live* (regenerated, do NOT hand-edit): `flagships` (the whole array — see below),
    `contributions` (external PRs, all states merged/open/closed), `issues`, `advisories`,
    `meta.syncedAt`.
- **`flagships`** — the *selected work* section, and it is **discovered, not hand-picked**:
  `sync-profile.mjs` takes every public, non-fork, non-archived `kanywst` repo with **at least
  one star** and ranks them by star count. So the section maintains itself — a repo that earns
  its first star joins on the next sync, and there is no `featured` flag or manual order to
  keep in step. To change *how a discovered repo reads* (not whether it appears), edit
  `scripts/taglines.mjs`: `TAGLINE_BY_REPO` overrides the GitHub description, `LANG_BY_REPO`
  the language for repos GitHub can't classify. Both fall back to live metadata, so an
  unlisted repo still renders. The UI podiums the top 3 (crown on #1) and lists the rest.
- **`advisories`** — the *upstream — security advisories* section, regenerated by
  `scripts/sync-advisories.mjs` from the live GitHub advisory API. Do NOT hand-edit the array.
  The source-of-truth is the `ADVISORY_SOURCES` list at the top of that script: one line per
  advisory kanywst has filed. Only `published` advisories render (draft/triage/closed 404 and
  are skipped), so an entry appears on the site the day it goes public and its CVE/severity
  fill in automatically. **When a new advisory is filed, add one line to `ADVISORY_SOURCES`**
  (`{ repo, ghsa, domain }`, plus `title` to override the API summary, plus `cve` only to pin a
  downstream-assigned CVE the upstream GHSA doesn't carry — e.g. kuma's finding is CVE-2026-18677
  via Kong Mesh but the kumahq GHSA shows cve=null). Rows sort CVE-first, then by severity.
- **`src/App.tsx`** — renders everything from that JSON. A minimal hero is the landing;
  pressing **Space** (collapsed only) reveals the detail; **Esc** / the footer button
  collapse. Detail sections: *selected work* (star-ranked podium + rows) → *upstream pull
  requests* (an org-avatar "contribution cloud" sized by PR count, plus a merged/open/closed
  filter with closed hidden by default) → *issues filed* → *0-draft* (avatar + language-dotted
  cards). The PR and issue lists render a `PREVIEW_ROWS` slice with a *show all* expander,
  because they run to dozens of rows and would otherwise bury everything below them. The
  cloud and lists are **derived** from `contributions`/`issues`, so new data needs no UI work.
- **`scripts/sync-profile.mjs`** — refreshes the live half via `gh` and writes `profile.json`.
  `domain` tags come from the `DOMAIN_BY_REPO` table at the top of the script (keyed by
  `owner/repo`), so re-syncs never lose tags. Aborts rather than write stale metadata if the
  PR fetch is empty.
- **GitHub Actions** (two workflows, intentionally separate):
  - `deploy.yml` — build + deploy Pages on every push to `main`.
  - `sync-profile.yml` — daily cron: run the sync script, and *only if profile.json changed*
    commit it and **build + deploy in the same job**. It self-deploys because a push made
    with `GITHUB_TOKEN` does NOT trigger `deploy.yml` (GitHub's loop-prevention).

The matching driver skill is `/sync-profile-site` (refresh data + verify build, stops before
commit/PR).

## Gotchas (learned the hard way)

- **TypeScript version skew breaks CI silently.** `package.json` pins `typescript: ^6.0.3`.
  TS 6 turns deprecated `tsconfig` options into *hard errors*. A stale local `node_modules`
  (e.g. TS 5.9) will pass `npm run build` while CI fails. **Run `npm install` so local TS
  matches CI before claiming a build is green.** The configs are already modernized
  (`moduleResolution: "bundler"`, `src/vite-env.d.ts` for `*.css` side-effect imports) — keep
  them that way.
- **`gh search` limit in `sync-profile.mjs` must stay high (1000).** kanywst opens hundreds of
  self-PRs (agent loops); a low limit returns only the most-recent and silently hides older
  *external* contributions.
- **Aesthetic is deliberate: minimal, monospace (Geist Mono), dark, teal accent `#5eead4`.**
  Extend this skin; do not introduce a new design language or restyle on your own initiative.
  "make it nicer" means refine the existing look, not replace it.
- **Geist Mono is self-hosted on purpose — do not "simplify" it back to Google Fonts.** The
  Google Fonts build is a different, stripped font: 52 glyphs, *zero* OpenType features and
  *zero* box-drawing glyphs, against 1159 glyphs and `ss01`–`ss11` in the official build (both
  verified with fontTools). On that build `font-feature-settings` is silently a no-op. The
  vendored `public/fonts/GeistMono-Variable.woff2` is the official variable file: 71 KB covers
  weights 100–900, loads same-origin with no third-party handshake, and is SIL OFL 1.1 (licence
  alongside it). The stylistic sets are deliberately left *off* — switching them on would change
  every `a` and `l` on the page, which is a look change, not a fix.
- **The colour tokens are contrast-tuned; check before darkening any of them.** `--fg` is
  `#ededed`, not `#ffffff`, because pure white on `#0e0e0e` is 19.3:1 / APCA Lc −107.6 — past
  the Lc −90 dark ceiling, where white haloes into the background. Every text tier clears WCAG
  AA against `--bg`; `--faint` (3.82:1) is reserved for *non-text* marks only — dots and rules,
  never a value someone is meant to read. The three `--line*` alphas are tiered by job (row
  rule / card border / structural rule), not interchangeable.
- **`letter-spacing` in `em` computes once and inherits as an absolute px length.** Any rule
  that steps `font-size` must re-declare `letter-spacing: var(--track)` or it silently inherits
  the 14px-computed value and ends up under-tracked.
